TENANT PLATFORM ENGINEERING

IDP Integration & Discovery Contract

Tenant applications consume AWS capabilities via Backstage, OpenChoreo, or CLI scaffolders without ever hardcoding AWS IDs. Foundation stacks publish parameters to SSM Parameter Store, and tenant Terraform queries them dynamically.

📦 Versioned Capability Modules

Capabilities (postgres, s3, workload-iam) are tagged and versioned independently via Google's release-please (e.g. postgres-v1.0.0). IDPs consume standard release tags with pinned semantic versions.

git::...//iac-modules-repo/data/postgres?ref=postgres-v1.0.0

🔍 The SSM Discovery Contract

Tenant configurations never require manual copy-pasting of VPC IDs or subnet CIDRs. The discovery-publisher module creates a unified catalog in AWS Systems Manager Parameter Store within each workload account.

docs/DISCOVERY_CONTRACT.md

🛡️ Hardened Tenant Isolation

Tenant applications run strictly in private subnets with no public IPv4 addresses. Every role assumed by tenant services or ACK controllers must carry the platform-workload-boundary IAM permissions boundary.

arn:aws:iam::...:policy/platform-workload-boundary
