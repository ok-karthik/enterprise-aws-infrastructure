# Live Stacks (`iac-live-repo`)

Declarative Terragrunt live configuration for every AWS account of the platform: the landing zone (management, security, network, observability) and the workload accounts (`workloads-dev` in NonProd, `workloads-prod` in Prod).

## How it is laid out

The folders show the AWS Organizations OU tree: OU, then account, then region, then stack. A reader sees at once what is an OU and what is an account.

```
iac-live-repo/
  root.hcl                  # the only root: provider, backend, tags, and the only file that looks anything up
  _config/                  # the account registry (accounts.hcl), regions.hcl, organization.hcl (also holds the OU tree)
  _bootstrap/               # Day-0 CloudFormation stack and bootstrap.sh
  root/management/                       # OU Root
  security/{log-archive,security-tooling}/   # OU Security
  infrastructure/{network-hub,shared-services,observability}/   # OU Infrastructure
  workloads/nonprod/workloads-dev/       # OU Workloads > NonProd
  workloads/prod/workloads-prod/         # OU Workloads > Prod
    <region or _global>/<stack>/terragrunt.hcl     # under every account folder
```

- The OU folder is the OU name in lowercase; a child OU sits under its parent; the organization root is `root/`. OUs without an account that has stacks (Sandbox, Policy-Staging, Suspended) have no folder yet.
- The OU tree has one source, `_config/organization.hcl` (`organizational_units`): the organization stack creates those OUs, and the scripts read the folder names from the same map. `scripts/check-account-registry.sh` fails if an account folder is not at the folder of its registry `ou`.
- The state key and the `Service` tag are `<account>/<region>/<stack>`: `root.hcl` uses the last three folders only. The OU folders are for people, so moving an account to another OU never moves state.
- The folder path is the configuration: `<account>` must be a key in `_config/accounts.hcl`, `<region>` is an AWS region, and `_global` means "account-wide, run from the primary region".
- Each `terragrunt.hcl` is the whole stack: module source, dependencies and every input. It includes `root.hcl` and nothing else. `scripts/check-account-registry.sh` fails if a stack uses `read_terragrunt_config`, `get_env(` or another `find_in_parent_folders`.
- A stack reads account and region values as `include.root.locals.<name>` (`account_name`, `account_id`, `env`, `ou`, `ou_path`, `alias`, `owner`, `data_classification`, `aws_region`, plus `registry`, `regions`, `organization`).
- Module sources are always the local `iac-modules-repo/` checkout.
- `_config/accounts.local.hcl` (gitignored) holds the real account ids and emails; CI reads the same text from the `ACCOUNTS_LOCAL_HCL` repository variable.

### Move an account to another OU

1. Change `ou` in `_config/accounts.hcl`. The account-factory stack moves the account in AWS on apply, but only for accounts with `create = true`; an account made by hand must be imported into account-factory first, otherwise only the folder and the registry change.
2. `git mv` the account folder to the new OU folder (for example `git mv iac-live-repo/workloads/nonprod/workloads-dev iac-live-repo/workloads/prod/workloads-dev`).
3. Run `scripts/check-account-registry.sh` and `make org-tree`. **No state move:** the keys are `<account>/<region>/<stack>`.

## Status Legend

| Status | Meaning |
|---|---|
| ✅ **applied** | Applied to AWS; proof linked. |
| 📝 **plan-only** | Syntactically valid, linted, tested offline; not applied (pending account creation, sandbox setup or cost considerations). |
| 📐 **design-only** | Architectural blueprint tested offline; not wired into a live stack. |
